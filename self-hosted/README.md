# 장비 캘린더 사용 안내

## 내부망 시험 시작

이 프로그램은 이 PC에서 직접 실행하는 무료 자체 호스팅 프로그램입니다. 예약과 장비 정보는 서버 PC의 `data` 폴더에 SQLite 파일로 저장되며, 별도의 클라우드 예약 서버를 사용하지 않습니다. 서버 PC가 켜져 있고 서버 실행 창이 열려 있어야 다른 사용자가 접속할 수 있습니다.

1. `start-calendar.cmd`를 실행합니다. 표시되는 주소 중 공유하려는 내부망의 IPv4 주소를 입력합니다. 비워 두면 이 PC에서만 접속할 수 있습니다. Python 3.9 이상이 필요합니다.
2. 서버에 표시된 주소를 이 PC의 웹 브라우저에서 엽니다. 주소를 비워 실행한 경우 `http://localhost:8765`입니다.
3. 내부망 주소를 입력해 실행한 경우, 같은 내부망의 다른 기기도 `http://서버PC의-IPv4주소:8765`로 접속합니다. 예를 들어 서버 주소가 `192.168.0.20`이면 `http://192.168.0.20:8765`입니다. 이것은 예시 주소입니다. 해당 네트워크 주소로만 수신하므로 다른 네트워크 주소나 `localhost`로 접속하려면 다시 시작해야 합니다.
4. 서버 창을 닫거나 `Ctrl+C`를 누르면 서버가 종료됩니다. 백그라운드에서 실행 중인 서버는 `stop-calendar.cmd`로 종료할 수 있습니다. 외부 PC 접속이 되지 않으면 같은 내부망인지, 주소가 맞는지, 회사 보안 정책과 방화벽에서 해당 포트가 허용되는지 확인하세요. 이 프로그램은 방화벽 설정을 자동으로 변경하지 않습니다.

초기에는 **내부망 시험 모드**로 시작합니다. 로그인 버튼을 누르고 시험용 이름을 입력한 뒤 오른쪽 장비 영역의 `+`로 장비를 등록합니다. 이름과 장비는 실제 조직 정보 대신 시험용 값으로 먼저 확인하세요. 시험 모드에서는 누구나 이름을 입력해 다른 사람인 것처럼 사용할 수 있으므로 실제 예약 운영이나 신원 확인에 사용하면 안 됩니다. 내부망 HTTP 통신은 암호화되지 않습니다.

## 예약 사용

- 장비별 색상은 오른쪽 `장비`의 추가 또는 수정 창에서 고릅니다. 장비 이름을 누르면 해당 장비의 표시를 켜고 끕니다. 현재는 로그인한 사용자가 장비를 추가하고 수정할 수 있습니다.
- 상단 `+` 또는 오른쪽 `예약하기`를 눌러 장비와 시작·종료 시간을 입력합니다. 서버가 저장 시각에 예약 겹침을 검사합니다. 다른 장비의 같은 시간 예약은 가능합니다.
- 종료 시각은 사용이 끝난 시각입니다. 예를 들어 `09:00` 종료와 `09:00` 시작은 서로 겹치지 않습니다.
- 월별 예약의 `→`와 `←`는 다음 날로 이어지거나 전날부터 이어진 예약입니다. 날짜를 선택하면 오른쪽의 24시간 막대와 예약 가능 구간에서 사용이 끝나는 시각을 볼 수 있습니다. 장비 목록과 선택 날짜 현황은 각각 스크롤됩니다. 모바일에서는 달력의 모든 요일과 주가 한 화면에 표시되며, 일정이 많아 `+n개`로 줄어든 날짜는 그 표시를 눌러 상세 현황을 볼 수 있습니다. 주·일 보기는 상단 전환 버튼으로 엽니다.
- 예약을 클릭하면 전체 장비명, 사용자, 시작·종료와 메모를 볼 수 있습니다. 자기 예약만 수정·삭제할 수 있습니다. 장비 목록과 일정은 약 15초 간격으로 갱신되며, 충돌 검사는 저장할 때 즉시 서버에서 수행합니다.
- 모든 시간은 한국 시간(KST)입니다. 이 앱은 장비 등록·수정은 제공하지만 장비 삭제 기능은 제공하지 않습니다.

## Google 계정 연결: 도메인과 HTTPS 준비 후

Google은 웹 애플리케이션의 인증 반환 주소에 일반 사설 IP 주소나 HTTP를 허용하지 않습니다. `localhost`는 같은 PC에서 개발용으로 쓰는 예외이며, 다른 내부망 PC에서 접속할 때의 대안은 아닙니다. 따라서 내부망 시험 단계와 실제 Google 로그인 운영 단계를 구분합니다.

1. 소유하거나 사용 권한이 있는 도메인을 서버로 연결하고, 유효한 HTTPS 인증서를 준비합니다. 외부 접근을 열기 전에는 조직의 네트워크 정책과 접근 범위를 확인하세요.
2. Google Cloud의 OAuth 동의 화면을 설정하고 **웹 애플리케이션** OAuth 클라이언트를 만듭니다. 승인된 리디렉션 URI에 `https://실제도메인/auth/google/callback`을 정확히 입력합니다. 테스트 상태인 Google 앱은 Google Cloud에서 허용한 테스트 사용자만 로그인할 수 있습니다.
3. 이 폴더의 `config.example.json`을 `data/config.local.json`으로 복사하고 `public_base_url`, `google_client_id`, `google_client_secret`을 실제 값으로 바꿉니다. `demo_mode`는 `false`로 둡니다. `allowed_emails`에 사용할 Google 계정의 이메일 주소를 넣으면 목록에 있는 계정만 로그인할 수 있습니다. 빈 배열 `[]`은 인증된 모든 Google 계정을 허용하므로 운영 범위에 맞게 설정하세요.
4. 유효한 인증서와 개인 키를 직접 서버에 적용하는 예시는 다음과 같습니다. 다른 HTTPS 역방향 프록시를 이용하는 경우에도 `public_base_url`은 사용자가 실제로 접속하는 HTTPS 주소여야 합니다.

   ```powershell
   python server.py --host 0.0.0.0 --port 443 --cert C:\certs\fullchain.pem --key C:\certs\privkey.pem
   ```

5. 브라우저에서 설정한 HTTPS 주소로 접속해 Google 로그인과 다른 사용자 계정의 접근 범위를 실제로 검증합니다. 첫 로그인 시 예약에 표시할 실명을 입력합니다. 서버는 Google 계정의 고유 식별자로 사용자를 구분합니다. 사용자가 입력한 이름 자체를 실명 인증하는 기능은 없습니다.

인증 설정을 만든 이후의 실제 Google 로그인, 인증서 갱신, 도메인 연결, 방화벽과 외부 접근 정책은 별도로 확인해야 합니다. Google 로그인 설정 전에는 로그인 버튼이 비활성화됩니다. Google 인증에는 인터넷 연결이 필요합니다.

공식 참고: [Google 웹 서버 OAuth 설정](https://developers.google.com/identity/protocols/oauth2/web-server), [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect).

## 데이터와 백업

- `data/calendar.sqlite3`에 사용자, 장비, 예약과 로그인 세션이 저장됩니다. 프로그램을 종료한 뒤 `data` 폴더를 안전한 위치에 복사해 백업하세요. 폴더에는 로컬 Google 설정과 비밀값이 포함될 수 있으므로 공유하지 마세요.
- 시험 데이터를 운영 데이터와 섞지 않으려면 서버를 종료한 상태에서 `data` 폴더를 안전하게 별도 보관하고 새 데이터 폴더로 시작하세요. 기존 데이터는 삭제하지 마세요.
- 운영 전에는 접속 대상, 백업·복원, 인증 및 권한, HTTPS와 서버 재시작 절차를 실제 환경에서 검증하세요.
- 글꼴은 Wanted Sans이며 `web/OFL.txt`에 라이선스가 포함되어 있습니다.
